# Issue #112 — isolated experimental compact transport, revision 1

Based on main after PR #111. Work specification `PushPull_Specyfikacja_Kopii_i_Dane_po_PR105.md` was not available in the repository/workspace; its contents were not inferred. This document defines the experimental contract proposed by this PR, not an existing approved Work contract or a production replacement for v1–v6.

`openCompactBackup(Blob, {signal, limits})` verifies the entire container before returning a frozen manifest and async `readObject(id)` iterator. No database, network, restore, UI, production export or precache dependency is added. Original readers remain unchanged. Object content is opaque bytes: application-level semantics and restore suitability are deliberately not claimed.

Wire: `PPC1` magic, big-endian uint32 manifest length, 32 raw SHA-256 bytes of the exact manifest, UTF-8 JSON manifest, then consecutive binary payloads in descriptor order. No base64 or repeated escaped full JSON. Manifest exactly `{format:'pushpull-compact',version:1,chunks,objects}`. Each chunk exactly `{storedBytes,decodedBytes,storedSha256,decodedSha256,compression:'none'|'gzip'}`. Object exactly `{id,parts,bytes}`. Parts are ordered zero-based chunk references; objects may share chunks, but logical bytes count each reference. IDs are unique, every chunk must be referenced, no external references or recursive archive interpretation. Arrays preserve order. Missing/trailing bytes, unknown fields, duplicate JSON keys, invalid UTF-8, hashes, sizes, references and unsupported versions fail closed. Header hash binds the entire manifest; descriptor hashes bind every payload. SHA-256 is integrity, not authentication against an attacker who rewrites hashes.

Limits: 512 MiB stored file and total logical/physical decoded bytes, 1 MiB manifest, 4096 chunks/objects/parts per object, 2 MiB stored and 4 MiB decoded per chunk, JSON depth 32 and 100000 tokens, 30 seconds elapsed. Options may only lower limits. These are experimental budgets, not measured Pixel guarantees or increases to legacy format limits. Declared budgets checked before decompression; streamed output checked before copying into a single bounded destination. Every fragment is verified sequentially and discarded; iteration rereads and rechecks fragment bytes from the immutable Blob. No complete 200 MB string is allocated. Consumers must avoid collecting all yielded chunks. Blob backing, crypto, gzip and browser internal buffers remain outside exact JS memory accounting. No RSS guarantee; tests under old-space caps do not represent physical Android RAM measurements.

Abort/time are checked across IO, digest and decompression steps. Abort cancels an active decompression reader. Synchronous JSON validation, pending Blob IO or crypto cannot be physically preempted; time bound detects overrun at the next checkpoint, not a hard watchdog. Caller can use a worker for hard termination; no production worker is integrated here. No partial handle is published. After opening, the same cancellation/deadline applies to iteration.

Synthetic Node tests cover gzip/none, Unicode/opaque content, corruption, truncation/trailing bytes, rehashed malformed references/descriptors, duplicate identities, unused chunks, zip-bomb expansion, lower-only budgets and cancellation. Chromium tests exercise offline module operation under a 64 MiB old-space cap; this is not full round-trip, real Drive or Pixel acceptance. Existing regression runs cover legacy formats and application behavior. Exact results are recorded in PR.

Next stage: separately reviewed writer with lossless domain graph, metadata and full synthetic round-trip, including UTF-16 string evidence encoding. No size savings claimed before that work; no writer, import, migration, automatic backup (#109), or user database access in this PR.
