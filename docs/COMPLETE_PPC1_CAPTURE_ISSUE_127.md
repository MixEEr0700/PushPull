# #127 — read-only live capture of the complete PPC1 contract

Base main `3fbd6f8` (merged #125), governed by #123. Uses the unchanged #125 envelope, writer, reader, training validators and full journal materialization. No production export/import switch, restore, Matrix, Drive, schema change, migration or source writes. No private device database accessed.

## API and coverage

`model/complete-backup-capture.mjs` exports `captureCompleteContract(options)` and `writeCapturedCompleteContract(options)`. The former returns an immutable, validated existing complete-contract object; the latter passes that captured object through the existing complete writer. This API is isolated and is not registered as a production or service-worker asset. Future UI integration must supply worker/lifecycle handling separately.

All 19 stores are enumerated using native IDB cursors, not reconstructed from current training UI state: meta, plans, planVersions, exercises, sessions, entries, sets, notes, changes, backups, journalObjects, journalMetadata, journalSessions, journalResults, journalSnapshots, journalArchives, journalIndex, journalState, journalCheckpoints. Every field is retained, including inactive rows, retained rescue evidence, unknown meta fields, drafts/conflicts and settings/Drive metadata. The exact store inventory, database version, key paths and absence of autoIncrement are checked. Missing/extra stores, absent database, inactive conversion or invalid active graph fail closed. Opening an absent database aborts the native upgrade and leaves no created database; the capture never creates stores.

Local enumeration uses the existing five classified sources: `pushpull_skeleton_v1`, `pushpull_indexeddb_owner`, `pushpull_skeleton_v1_backup_*`, `pushpull_workout_draft_v1:*`, `pushpull-note-ui-v1:*`, including tombstones and invalid raw JSON. Values are copied verbatim, not parsed/normalized. Unrelated origin keys are excluded. New unclassified lowercase `pushpull*` keys cause refusal instead of silent omission. Existing absent optional keys remain explicitly absent; unavailable storage refuses. CacheStorage contains rebuildable code, not a new training-data source (inventory #124).

## Consistency argument and limits of the claim

1. A single native **readonly** transaction spans all 19 stores. Its cursors return one consistent IDB view; conflicting readwrite transactions wait until its completion. localStorage is synchronously enumerated in the final cursor callback while that transaction still holds its IDB scope, then compared again on completion. There is no asynchronous gap between individual localStorage reads in that callback in this document.
2. The detached records are frozen. Existing full journal materialization audits hashes, references, indexes, checkpoints and active state; existing complete-contract validation checks the matching active protocol marker/epoch, root and exact logical-source/ledger equality. No `reload`, `flush` or root-only assumption is used as evidence for auxiliary stores.
3. After validation, a second readonly all-store transaction compares **every field of every record**, streaming cursors against the first ledger without retaining another full ledger. Any changed/added/deleted record fails, including draft or Drive metadata changes without a journal revision increment. The local key/value inventory must still match, including a synchronous check in this transaction's final cursor callback and at completion. A storage-event listener also rejects cross-document changes/clear operations, including observed change-and-restore (ABA) events.
4. IDB native completion, revision/schema guards, signal/time checks and all comparisons must succeed before the API resolves. A change after the capture point does not retroactively invalidate that fixed snapshot; future consumers must use their own destination CAS. No source write transaction, global lock, polling retry or state mutation is performed. Readonly cursor transactions necessarily delay overlapping writes for their duration; expensive semantic validation runs outside these transactions.

**This is not a cross-IDB/localStorage transaction.** localStorage has no multi-key snapshot/lock against another document. Repeated matching synchronous inventories plus delivered storage events are observational stability evidence, not a proof against every adversarial cross-process schedule, suspended document or as-yet-undelivered event. The unchanged contract therefore deliberately retains `scope:'supplied-persistent-snapshot'` and `otherTabs:'unknown'`; it is NOT promoted to a device-complete claim. Other tabs' unpersisted editor memory cannot be captured here. Known/observed conflicts fail closed; undetectable schedules cannot be certified complete. A future stronger all-tab complete-production guarantee needs a separately approved cooperative writer/capture barrier. No such write mechanism is introduced in this read-only stage.

## Resource and failure policy

Capture-only limits may only be lowered: 10,000 physical/local entries (matching the contract cap), 64 MiB of conservative retained input charge, 100,000 visited JSON nodes, depth 32, elapsed 30 s. The input charge counts UTF-16 strings and keys plus fixed node charges without allocating serialized full-model JSON. It is a refusal threshold, **not a measured heap upper bound**: native IDB clones one record before JS can inspect it; JSON materialization and existing writer/reader allocate additional graphs/buffers. Semantic/resource errors, permission errors, native transaction errors, cancellation and schema/revision changes return no partial result/file. Opening has a deadline/abort listener and late connections close. Active scans check cancellation/time on cursor callbacks; validation uses existing abortable routines. A single native clone or synchronous validator task cannot be preempted mid-task. No increased existing PPC1/protocol limits.

Records use deterministic native primary-key order, local keys are sorted. This changes no source records, source field order, logical result/series order or semantics. The isolated wrapper may duplicate memory as required by the unchanged writer; constant-memory production export is not claimed. The 64 MiB capture guard can intentionally refuse larger source databases, including some 200+ MB JSON histories; do not claim device capacity or silently lift it.

## Verification

Targeted Node tests cover namespace classification, strictly lower-only budgets and pre-abort without opening storage. Real Chromium synthetic tests enumerate all 19 populated stores, compare every field through PPC1 roundtrip and compare complete IDB/localStorage before/after. Additional cases: large Unicode raw archive, restart recapture equality, offline, native readonly transaction modes/scopes, two-tab metadata changes with unchanged journal root, epoch/revision changes during validation, other-tab localStorage ABA, same-tab persistent buffer changes, pre/midflight cancellation, aborted IDB transaction, simulated quota/security read exceptions, missing database (no creation), missing store, unknown PushPull key, corrupt graph, and lowered record/memory/node/depth/time budgets. Injected quota exception verifies error propagation; it is not a real disk-exhaustion test (this API does not write).

Final outcomes and one full CI run are recorded in the PR. Prior reader/writer/contract and production storage/import tests are inherited unchanged; final CI exercises the complete suite. No physical Pixel 9 measurements, production export → clean-profile production import → restart → full durable comparison, restore of the complete envelope, Drive or automation are implemented/verified. Full recoverability remains unproven. Next step: separately reviewed destination restore semantics and production full roundtrip; do not replay old epochs/device identity/outbox blindly.
