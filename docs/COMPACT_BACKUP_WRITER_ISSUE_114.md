# Issue #114 — isolated PPC1 model writer and exact round-trip

Based on main `3c5ea5e`, after PR #113. Uses its unchanged PPC1 transport reader. No production import/export, Drive, UI, storage, migration, service worker or automatic backup integration. Only synthetic fixtures are read. Work specification is not available in this workspace; no contents inferred.

## API and graph revision 1

`writeCompactModel(model, {signal, limits, compression}) -> Blob`; `readCompactModel(blob, options) -> complete reconstructed model`. The latter is an isolated in-memory domain mapper, not a production importer or restore. Writer captures all enumerable own fields before its first await, so later caller edits cannot change the backup. Plain objects (including null-prototype dictionaries), dense arrays, finite numbers, strings, booleans and null are accepted. Rejects getters, symbols, hidden properties, extended/sparse arrays, cycles, undefined, BigInt, Date and nonfinite numbers instead of silently losing them. Mapping has value semantics: null-prototype dictionaries are reconstructed as ordinary objects, and structurally equal objects can share one reconstructed reference. No mutation of input. Reconstructed output is deeply frozen, so shared references cannot silently propagate edits across snapshots; future import must follow existing validated model handling. Callers must not treat reconstructed reference identity or property descriptors as persistent domain data.

Every field is mapped, including unknown compatibility/settings fields, session results, source metadata, original raw archives and complete plan/snapshot models. This is not an embedded legacy v3 export. A `graph` PPC1 object carries UTF-8 JSON `{format:'pushpull-model-graph',version:1,root,nodes}`; root/children are integer node references. Nodes are two-element tuples: `value` (boolean/null), `number` (canonical number string, including -0), `string` (object id `s<node-index>`), `array` (ordered references), or `object` (ordered key-node/value-node pairs). Object keys are string nodes. Duplicate keys, bad types, unknown/unreachable nodes, cycles, missing strings and unused transport objects fail closed. Properties such as __proto__ are defined as own data without prototype mutation. Semantic validity of a training plan/result is not inferred from lossless mapping; existing application validators remain necessary for any future restore.

Strings are UTF-16LE code units in separate objects, preserving lone high/low surrogates, NUL, normalization forms, whitespace and opaque archive texts without parse/reserialize. Strings are split at even byte boundaries. Equal strings and structurally equal subtrees are interned. SHA-256 deduplicates identical bounded binary fragments; descriptors retain ordered references. Each unique fragment is gzip compressed only if smaller, otherwise stored unchanged. `compression:false` permits none-only tests. Manifest and header follow PR #113 exactly, including all stored/decoded hashes. Entire file is validated by the existing reader before it can be returned. Reconstruction opens the same reader and iterates its verified objects; no production database writes.

## Limits and costs

Unchanged PPC1 limits apply; overrides may only lower them. Writer fragments <=256 KiB (or smaller supplied stored/decoded limits), 10000 unique graph nodes, <=10000 own properties per object/array, <=100000 visited properties in capture and model depth <=64. Graph JSON itself is capped by manifestBytes (normally 1 MiB) and parsed with existing bounded duplicate-key/token/depth checks. All chunks and all string/graph logical bytes count against reader budgets. Refusal returns no complete file/model. No limits were raised to fit the native V2 fixture.

No full-model JSON serialization or huge UTF-8/escaped archive copy: only bounded binary strings and bounded graph/manifest are serialized. Source model, graph/interner and output Blob remain resident; reconstruction materializes a full model and full strings. This is not constant-memory restore or zero-copy. JS heap caps do not cap native crypto/gzip/Blob RSS. Capture and bounded JSON/UTF16 loops run synchronously, with cooperative checkpoints, not a production worker: no claim of main-thread responsiveness for a 208 MB real source. Abort/deadline checks surround async operations; native compression/digest cannot be physically preempted. Reader keeps its original cooperative deadline. Writer additionally checks its total elapsed deadline after reader verification.

## Synthetic evidence

Independent fixture uses the existing native V2 journal builder (four V2 workouts, additional TEST plan, snapshots, original instructions, notes, L/P, drops, results), plus opaque/null/empty/invalid and Unicode archives and arbitrary settings. Full deepStrictEqual of every property after write -> existing reader -> readObject -> model reconstruction; no counter-only acceptance. Other cases: structural/chunk dedup, none/gzip, late input mutation, rehashed malformed graphs, damaged/truncated files, limits, unsupported values and abort.

Example Node profile: two identical 8 MiB raw archives, legacy fixture and synthetic fields: JSON 16784699 bytes, PPC1 54874 bytes, write ~259 ms, read/check ~404 ms, process RSS ~158 MB. Deliberately highly repetitive data; not expected real-user ratio. An independent Node process round-trips one 8 MiB archive with 64 MiB V8 old-space, process RSS ~108 MB; demonstrates why old-space is not total RAM.

Chromium offline, viewport 390px, 64 MiB old-space: full structural JSON comparison including lone surrogates, source immutability and truncation rejection, 4 MiB repetitive archive. Final local run: JSON 4201573 bytes, PPC1 51622 bytes, write ~790 ms while the full Node suite ran concurrently. Timing is load-sensitive; the earlier pre-interning run was ~394 ms. Full regression/CI results are in PR. Build and SW hashes checked without adding these experimental modules to production precache. No Pixel 9 or real Drive result is claimed.
